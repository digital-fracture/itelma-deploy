
# Предобработка даных

Для предотвращения искажения результатов был разработан пайплайн, очищающий сигнал. А именно:

1. **Удаление выбросов на малых промежутках до 5 секунд**  
   Убираем резкие скачки и физиологически недостижимые значения (например, ЧСС < 50 или > 220 уд/мин), которые могут возникать из-за помех или сбоев датчиков. Это сохраняет реальную динамику сигнала и предотвращает ложные срабатывания на артефакты.

2. **Интерполяция пропущенных значений — только для коротких разрывов**  
   Пропуски в данных неизбежны, особенно при телеметрической регистрации. Мы заполняем **только малые разрывы (до 5 секунд)**, чтобы не искажать физиологическую картину и не «додумывать» длинные участки.

  - **Как это работает:**
    - Между двумя соседними точками с разрывом ≤ 5 с вставляются новые точки с шагом, соответствующим типу сигнала: `0.25 с` для FHR, `1.0 с` для UC.
    - Используется либо линейная интерполяция, либо PCHIP (shape-preserving кубическая), если вокруг достаточно точек; при недостатке контекста — автоматически переключаемся на линейную.
    - Экстраполяция **не применяется**: начало и конец записи остаются без изменений.
    - Все значения клиппятся по физиологическим границам: FHR → `[50, 220]`, UC → `[0, 80]`.

  - **Выход и метаданные:**
    - Каждая точка помечается: `source="raw"` (исходная) или `source="interp"` (интерполированная).
    - При агрегации до 1 Гц формируются маски:
      - `*_mask=1` — точка валидна (исходная или из малого разрыва),
      - `*_mask=0` — длинная дыра (разрыв > 5 с),
      - `*_interp=1` — точка получена интерполяцией.

  - **Контроль качества:**  
    Если доля интерполированных точек превышает порог (например, 20–30%), сегмент помечается как **ненадёжный** и может быть исключён из анализа.

  - **Почему так?**  
    Короткие пропуски типичны для КТГ и безопасны для локального заполнения. Длинные разрывы оставляем «как есть», чтобы модель не обучалась на синтетических данных.

3. **Сглаживание шума с помощью скользящего среднего**  
   Для повышения устойчивости к высокочастотному шуму применяется усреднение в скользящем окне. Это делает сигнал более гладким и робастным, сохраняя при этом клинически значимые тренды и вариабельность.

# Высчитывание характеристик и модель предсказания гипоксии

## 1. Извлечение признаков из обработанных сигналов

После предварительной обработки сигналов **ЧСС (bpm)** и **сокращений матки (uterus)** из них вычисляются числовые метрики, которые помогают оценить состояние плода. Вот основные из них:

### Для сигнала ЧСС (bpm):

- **Средняя частота сердечных сокращений** — усреднённое значение ЧСС за всё время наблюдения.
- **Количество акцелераций и децелераций** — всплески и падения ЧСС, которые могут свидетельствовать о реакции плода.
- **Время тахикардии и брадикардии** — сколько времени ЧСС была выше или ниже нормы, включая степени тяжести.
- **Типы децелераций** — различаются **ранние**, **поздние** и **вариабельные**, определяются по соотношению с сокращениями матки.
- **Статус плода** — суммарная оценка состояния, рассчитанная по принятой методике.

### Для сигнала сокращений (uterus):

- **Частота сокращений** — сколько сокращений происходит в минуту.
- **Общее количество сокращений** — за весь период записи.

---

## 2. Формирование обучающей выборки

- **`X_train`** — это таблица, где каждая строка представляет один КТГ-запись, а столбцы — вычисленные метрики (например, средняя ЧСС, число децелераций и т.д.).
- **`y_train`** — вектор, в котором для каждого КТГ указано, была ли зафиксирована гипоксия (`1` — да, `0` — нет).

---

## 3. Используемые модели машинного обучения

Для классификации гипоксии были протестированы следующие модели:

- `LogisticRegression`
- `RandomForestClassifier`
- `KNeighborsClassifier`
- `SVC`

---

## 4. Обоснование выбора моделей

Выбор моделей был сделан с учётом специфики задачи — определение гипоксии плода по КТГ, где важны как точность, так и интерпретируемость.

| Модель                   | Почему выбрана для задачи гипоксии |
|--------------------------|-----------------------------------|
| **Logistic Regression**  | Проста в интерпретации: понятно, какие признаки влияют на результат (например, время брадикардии). Устойчива при небольших выборках. Хороша, если связь между признаками и гипоксией линейна. |
| **Random Forest**        | Устойчива к шуму (важно, так как КТГ могут содержать артефакты). Позволяет оценить важность признаков. Улавливает сложные, нелинейные зависимости. |
| **KNN**                  | Не делает предположений о распределении данных. Работает по принципу «похожесть с патологией» — интуитивно понятно врачу. Хорошо работает, если есть похожие случаи. |
| **SVM (с RBF-ядром)**    | Отлично справляется с нелинейными паттернами. Полезна, когда гипоксия проявляется в виде сложной комбинации признаков. Эффективна при небольшом числе признаков. |

---

## 5. Обоснование критериев отбора модели

- **Интерпретируемость** — особенно для врача, который должен понимать, на основании чего было принято решение.
- **Устойчивость к шуму** — важно, так как сигналы КТГ могут быть искажены.
- **Точность и чувствительность** — в задаче гипоксии **чувствительность (recall)** особенно важна, чтобы не пропустить патологию, но и **precision** не должна быть слишком низкой, чтобы избежать ложной тревоги.

## Модель краткосрочного прогноза и рисков (TemporalMTL)

**Идея.** Мультизадачная временная модель, которая одновременно:

* предсказывает профиль **FHR** на **60 с** вперёд;
* оценивает вероятности клинических событий.

**Вход.** Последние `N = 200` с КТГ (1 Гц): каналы **FHR** и **UC** + признаки *(baseline, STV, сглаженный UC)* и **маски пропусков**.

**Архитектура.** Encoder **TCN → лёгкий Transformer/BiLSTM**. Две головы:

* **Seq2Seq:** 60 точек FHR (1 Гц);
* **Классификация рисков:** `p_late_10m` (поздние децелерации за 10 мин), `p_hyp_5m` и `p_hyp_15m` (прокси-гипоксия).
  Обучение с **масками** — длинные разрывы не штрафуются.

**Реал-тайм.** Пересчёт каждые **1–15 с** по скользящему окну (если окно `< min_required` — возвращаем «недостаточно данных»).

**Что выводим врачу.**

* Короткие **фразы-алерты** (семафор), **калиброванные пороги** и **гистерезис**.
* Числа для дашборда: `p_late_10m`, `p_hyp_5m`, `p_hyp_15m`, `fhr_next60_mean`, `fhr_next60_min`.

**Надёжность.**

* Интерполируем только **дыры ≤ 5 с**, длинные — **маскируем**.
* **Калибровка вероятностей** (Platt/Isotonic).
* **Валидация по пациентам**.
  Ключевые метрики: **AUPRC/AUROC**, **TPR при ≤ 1 ложном алерте/час**, *lead-time*, **MAE(FHR)**.

## Описание алгоритма выявления late deceleration

### 1. Методы обработки и анализа физиологических сигналов

Алгоритм работает с двумя основными сигналами:
- **FHR (Fetal Heart Rate)** — частота сердечных сокращений плода.
- **UC (Uterine Contraction)** — сигнал сокращения матки.

Обработка включает:
- Вычисление базовой частоты FHR (baseline) на скользящем окне.
- Детекция падений FHR, удовлетворяющих критериям:  
  `ΔFHR ≥ 15 уд/мин` относительно baseline и длительность спада `≥15 секунд`.

---

### 2. Алгоритмы выявления аномалий и построения прогнозов

Для каждого выявленного падения FHR выполняются следующие шаги:

#### Шаг 1: Определение типа децелерации по форме
- Рассчитывается время от начала спада до минимума (**onset → nadir**).
- Если это время `≥30 секунд`, децелерация маркируется как **«плавная»** (gradual).

#### Шаг 2: Сопоставление с UC-сигналом
- Находится **пиковое время сокращения (UC peak)**.
- Проверяется временная связь:
  - Минимум децелерации должен наступать **после пика UC**.
  - Восстановление FHR (возврат к baseline) должно происходить **после завершения UC**.

#### Шаг 3: Финальная маркировка
Только те децелерации, которые удовлетворяют **всем трём условиям**:
1. ΔFHR ≥ 15 уд/мин, длительность ≥15 сек;
2. onset → nadir ≥30 сек (плавное падение);
3. nadir после UC peak, восстановление после конца UC,

— маркируются как **late deceleration**.

---

### 3. Обоснование выбора моделей и их характеристики

В данном алгоритме применяется **детерминированный правила-базированный подход**, основанный на клинических критериях ACOG/NICHD.  
Преимущества:
- Интерпретируемость.
- Надёжность при ограниченных данных.
- Соответствие стандартам клинической практики.






# Пользовательская документация

Пользовательская документация предназначена для **медицинского персонала** и подробно описывает работу с системой, включая два основных режима: **эмуляцию фетального монитора** и **панель врача (рабочее место)**.

---

### 1. Руководство пользователя для медицинского персонала

#### А. Главная страница (Выбор режима работы)

Главная страница системы является **не информационным сборником**, а точкой входа, предоставляющей выбор из двух ключевых вариантов использования:

1.  **Эмуляция фетального монитора (КТГ):** Режим для воспроизведения и анализа данных исследования КТГ.
2.  **Панель врача (Рабочее место):** Режим для управления пользователями, мониторинга в реальном времени и просмотра детальной статистики.

#### 1. Режим "Эмуляция фетального монитора"

Этот режим позволяет **воспроизвести исследование КТГ** из архивных данных для анализа, обучения или тестового прогона.

* **Начало эмуляции:** При входе на страницу необходимо **загрузить ZIP-файл** с данными исследования. После успешной отправки файла **начнется его эмуляция** в нижней части страницы.
* **Настройка критических параметров:** Под областью эмуляции расположены кнопки для **настройки** параметров, которые будут считаться **критическими** для данного исследования.
* **Основная аналитика:** Внизу страницы также отображается **основная аналитика**, соответствующая функционалу **классического фетального монитора**.
* **Завершение и предиктивная информация:**
  * По завершении первой части исследования (или всего исследования) появляется **модальное окно** с кнопкой для **продолжения**.
  * Сбоку от основного окна отображается **основная предиктивная информация** (прогноз), а также **указание текущих данных** (статус) исследования.

---

#### 2. Режим "Панель врача" (Рабочее место)

Этот режим является основным инструментом для работы врача с данными пациентов.

* **Список пользователей (Пациентов):** Сначала врач попадает на страницу со **списком пользователей (пациентов)**. Здесь осуществляется выбор необходимого пациента для дальнейшей работы.

#### Б. Страница Пользователя (Пациента)

При выборе пользователя открывается страница с его данными и инструментами мониторинга/анализа.

* **Подключение к КТГ в реальном времени:**
  * Если у выбранного пользователя **в данный момент идет исследование КТГ**, врач может **подключиться** к нему.
  * Это позволяет **посмотреть, что происходит на мониторе** КТГ **без физического доступа** к нему (удаленный мониторинг).
  * В этом режиме врач может **настроить для себя критические параметры** и **посмотреть в реальном времени предикты и аналитику**.
* **Основная информация о пользователе:** На странице отображается **основная информация** по пациенту.
  * Есть кнопка для **быстрого просмотра и изменения** этой информации.

---

### 3. Инструкции по интерпретации результатов анализа

#### А. Анализ исследований на странице пользователя

Врач имеет доступ к детальной статистике и визуализации исследований пациента.

* **Выбор исследования для анализа:**
  * Врач может **быстро посмотреть статистику** по **последнему проведенному исследованию**.
  * Также есть возможность **выбрать любое другое исследование** из архива, по которому будет отображаться **статистика и график**.
* **Работа с графиком:**
  * График исследования можно **подробнее рассмотреть, увеличив его** (функция масштабирования).
  * На графике будут **выделены области**, которые решение посчитало **"странными"** или **аномальными** (на основе алгоритмов выявления аномалий, описанных в п. 2 "Описание алгоритмов").

---

### 4. Рекомендации по использованию системы в клинической практике

* **Мониторинг без физического доступа:** Рекомендуется использовать функцию **удаленного подключения к КТГ** для оптимизации рабочего процесса и более быстрого реагирования на критические ситуации, особенно при одновременном наблюдении за несколькими пациентами.
* **Настройка критических параметров:** Врачи должны **настроить индивидуальные критические параметры** для каждого пользователя или группы пользователей, исходя из клинического случая, чтобы система максимально эффективно выделяла необходимые аномалии.
* **Анализ аномалий:** Особое внимание следует уделять **выделенным областям на графике**, которые были помечены системой как потенциально аномальные. Это должно служить отправной точкой для углубленного анализа данных и принятия клинических решений.
* **Формирование отчетов:** Врач может **распечатать отчет о последнем исследовании** (или выбранном исследовании) для включения в медицинскую документацию пациента. Рекомендуется использовать этот отчет для консультирования и междисциплинарного обсуждения.
